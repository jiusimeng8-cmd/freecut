# 云端 AI 剪辑器方向

> 状态：开发阶段方案草案
> 更新日期：2026-07-16

## 背景

当前已经有一套面向 ChatCut 的视频剪辑 skills，覆盖口播故事剪辑、字幕、画面、MG、媒体特效、声音和封面等工作流。现阶段希望提供一个更容易安装和使用的独立客户端，降低用户对浏览器、网络环境和外部编辑平台的依赖。

编辑器以 FreeCut 为基础独立开发，保留其时间线、预览、渲染、导出和本地项目能力，在此基础上增加 AI 对话侧边栏和云端 Agent 工具调用能力。

## 产品定位

产品由免费编辑器和云端 AI 剪辑能力组成：

- 编辑器客户端免费使用。
- 用户素材和项目默认保存在本地。
- 手动剪辑、项目保存和本地导出不依赖 AI 服务。
- AI 剪辑、转录、内容理解、素材生成和自动包装由云端完成。
- AI 服务不可用时，不影响已有项目的手动编辑和导出。

当前开发阶段优先验证产品能力和编辑闭环，不在编辑器中部署本地大模型。

## 核心体验

用户在编辑器侧边栏中直接描述需求，例如：

- 删除口癖和长停顿。
- 保留关于价格的部分，剪成 60 秒。
- 添加同步字幕并突出关键词。
- 在产品介绍处添加 B-roll。
- 调整人声音量并添加背景音乐。
- 为视频生成开场 MG 和封面。

AI 先读取项目、素材、时间线和转录信息，再生成结构化编辑计划。需要修改时间线时，由客户端执行明确的工具调用，并把执行结果返回云端 Agent。

## 技术架构

```text
Electron 客户端
├── FreeCut 编辑器
├── 本地项目与素材
├── AI 对话侧边栏
├── 编辑器 Tool Registry
├── 工具调用确认与撤销
└── WebSocket 会话桥接
          │
          ▼
云端 AI 服务
├── 用户与会话
├── Agent 编排
├── ChatCut skills
├── 模型与媒体分析
├── 转录和内容理解
└── 结构化工具调用
```

## 客户端与云端边界

### 客户端负责

- 导入、管理和预览本地素材。
- 保存项目和时间线。
- 执行时间线修改。
- 播放、撤销、恢复和导出。
- 采集 Agent 所需的项目上下文。
- 展示 AI 计划、进度、结果和错误。
- 将必要的音频、代理文件或画面采样上传到云端。

### 云端负责

- 理解用户自然语言需求。
- 调用 ChatCut skills。
- 转录、语义分析和镜头分析。
- 生成编辑计划和工具参数。
- 图片、视频、音乐、语音等生成任务。
- 长任务状态管理和结果回传。

云端不直接修改用户本地项目文件。所有编辑操作通过客户端工具执行，确保编辑器状态、撤销记录和最终项目一致。

## AI 工具调用链

```text
用户输入
  ↓
云端 Agent 读取项目上下文
  ↓
Agent 返回工具调用
  ↓
客户端校验参数
  ↓
调用 FreeCut 时间线 action
  ↓
客户端返回执行结果
  ↓
Agent 继续下一步或结束任务
```

工具返回结构示例：

```json
{
  "tool": "split_clip",
  "arguments": {
    "clipId": "clip-123",
    "timeSeconds": 12.4
  }
}
```

## 第一阶段工具范围

第一阶段只覆盖口播视频的主要闭环：

- `read_project`
- `read_timeline`
- `list_assets`
- `import_media`
- `read_transcript`
- `search_transcript`
- `split_clip`
- `trim_clip`
- `delete_range`
- `move_clip`
- `add_caption`
- `add_text`
- `set_volume`
- `add_broll`
- `export_video`
- `undo`

工具名称和参数尽量兼容现有 ChatCut skills，客户端内部再映射到 FreeCut 的时间线 action。

## 第一阶段 MVP

MVP 目标是完成以下流程：

```text
安装客户端
  ↓
导入口播视频
  ↓
AI 云端转录
  ↓
AI 删除口癖和停顿
  ↓
生成并添加字幕
  ↓
添加简单 B-roll
  ↓
用户预览和调整
  ↓
本地导出
```

第一阶段不追求完整替代剪映，也不一次性迁移所有 ChatCut 工具。优先验证 AI 是否能够稳定读取真实项目、执行编辑、反馈结果并保持可撤销。

## FreeCut 开发策略

- `upstream/main` 用于跟踪原始 FreeCut。
- 产品代码在独立分支持续开发。
- 尽量保留 FreeCut 的时间线和渲染核心结构。
- AI、云端连接和客户端能力放在独立模块。
- 对编辑核心的修改保持小而明确，便于吸收上游修复。

建议新增的主要模块：

```text
apps/
├── desktop/          # Electron 主进程、安装和更新
└── editor/           # FreeCut 编辑器

src/
├── features/agent/   # AI 侧边栏和任务状态
├── tool-bridge/      # Agent 工具与 FreeCut action 映射
└── cloud/            # 登录、会话、上传和流式通信
```

实际目录应优先沿用 FreeCut 当前结构，避免为了方案文档提前重构代码。

## 当前不做

- 不在客户端部署本地大语言模型。
- 不同时开发移动端。
- 不重写 FreeCut 时间线和渲染引擎。
- 不一次性实现全部 ChatCut skills。
- 不在第一阶段建设复杂模板商城和素材社区。
- 不让云端直接写入本地项目文件。

## 验证标准

第一阶段满足以下条件即可进入下一阶段：

1. 客户端可以稳定打开、保存和重新加载项目。
2. AI 可以读取时间线、素材和转录上下文。
3. AI 工具调用可以修改真实时间线。
4. 每次 AI 修改都可以撤销。
5. 客户端断网后仍能手动编辑和导出已有项目。
6. 一条真实口播视频可以完成从导入到导出的完整 AI 工作流。

## 后续方向

口播 MVP 稳定后，再逐步加入：

- 复杂字幕排版和关键词动画。
- Motion Graphics。
- 媒体特效和转场。
- 声音设计、配乐和语音生成。
- 封面和缩略图。
- 长视频切片和批量版本生成。
- 云端任务记录、额度和团队协作。
